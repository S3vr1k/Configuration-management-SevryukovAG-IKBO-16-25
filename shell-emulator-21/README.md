# Эмулятор оболочки - вариант 21

## Этап 1

Реализованы графический интерфейс, заголовок с именем пользователя
и компьютера, история команд, раскрытие переменных окружения,
заглушки ls и cd, команда exit и обработка ошибок.

## Требования

Python 3 с Tkinter.

## Подготовка и запуск

Команды выполняются из папки проекта:

```bash
python3 -m venv .venv
chmod +x run.sh
./run.sh
```

Прямой запуск:

```bash
.venv/bin/python -m src.main
```

## Команды и настройки

- `ls [путь]` — вывод имени команды и аргументов.
- `cd [путь]` — вывод имени команды и аргументов.
- `exit` — закрытие приложения.

Для ls и cd разрешён максимум один аргумент.
Аргументы с пробелами можно заключать в кавычки.

В аргументах раскрываются `$NAME` и `${NAME}`.
Неизвестные переменные сохраняются без изменения.
В текущем парсере подстановка выполняется после удаления кавычек,
поэтому переменные раскрываются и в одинарных кавычках.

Поддерживаются параметры --vfs и --script.
Виртуальная файловая система загружается из CSV на этапе 3.

## Структура

- `src/main.py`: функция main запускает приложение.
- `src/gui.py`: класс EmulatorWindow создаёт интерфейс;
  write выводит текст, on_enter обрабатывает Enter.
- `src/parser.py`: parse_command разбирает введённую строку.
- `src/shell.py`: execute_command обрабатывает команду.
- `tests/test_stage1.py`: автоматические проверки.
- `run.sh`: скрипт запуска.

## Тесты

```bash
.venv/bin/python -m unittest discover -s tests -v
```

## Примеры

Команды вводятся в окне приложения:

```text
ls /docs
cd "my folder"

unknown
exit
```

Неизвестные команды, лишние аргументы и незакрытые кавычки
вызывают сообщение об ошибке.

## Этап 2: конфигурация и стартовый скрипт

Добавлены параметры командной строки:

- `--vfs PATH` — путь к CSV-файлу VFS, загружаемому в память.
- `--script PATH` — путь к стартовому файлу команд.
- `--help` — справка по параметрам.

Без параметров оба пути имеют значение None.
При запуске значения отображаются в истории окна.

Стартовый скрипт — текстовый файл UTF-8 с одной командой на строку.
Пустые строки пропускаются. Поддержка комментариев не реализована.
Относительные пути при запуске через run.sh отсчитываются
от папки приложения.

Команды выполняются последовательно. В истории показываются
команды и результаты. При первой ошибке выполнение прекращается,
но окно остаётся открытым. Команда exit закрывает приложение
и прекращает выполнение последующих строк.

### Пример запуска

```bash
./run.sh --vfs fixtures/nested.csv --script scripts/stage2_ok.txt
```

### Новые модули

- `src/config.py`: parse_options разбирает параметры запуска.
- `src/startup.py`: run_script читает файл и выполняет команды.
- `src/gui.py`: run_startup показывает настройки и запускает скрипт.

### Проверочные сценарии

```bash
./scripts/check_config.sh
./scripts/check_errors.sh
```

Каждый сценарий последовательно запускает четыре экземпляра
приложения. Для перехода к следующему нужно закрыть текущее окно.

### Автоматические тесты

## Этап 3: виртуальная файловая система

Добавлена загрузка CSV в память. Исходный CSV открывается только
для чтения. Виртуальные файлы и папки на диске не создаются.
Данные загруженной системы доступны в `window.vfs.nodes`.
Без `--vfs` создаётся пустая корневая папка `/` в памяти.

На этом этапе `ls` и `cd` остаются заглушками и показывают аргументы.
Их полноценная реализация относится к этапу 4.

### Формат CSV

Столбцы должны идти в следующем порядке:

```csv
path,type,content_base64
/,dir,
/docs,dir,
/docs/hello.txt,file,SGVsbG8K
```

- `path` — полный виртуальный путь; вложенность определяется путём.
- `type` — `dir` для папки или `file` для файла.
- `content_base64` — содержимое файла в base64; у папок поле пустое.

Корень и родительские папки должны быть явно перечислены.
Узлы можно записывать в любом порядке. Пути должны быть уникальными,
абсолютными, без `.` и `..`, лишних разделителей и завершающего `/`
(кроме самого корня). Типы узлов и base64 проверяются при загрузке.
CSV читается как UTF-8 с поддержкой необязательной метки BOM.
Двоичные данные сохраняются в памяти как `bytes`.

### Сообщение при старте

Если внутри VFS есть файл `/motd`, его текст UTF-8 показывается
перед выполнением стартового скрипта. При отсутствии файла запуск
продолжается без сообщения. Папка вместо `/motd` или нетекстовое
содержимое считаются ошибкой.

Порядок запуска: параметры, загрузка VFS, список виртуальных путей,
сообщение motd, команды стартового скрипта.
При ошибке загрузки сообщение остаётся в окне, ввод блокируется,
стартовый скрипт не выполняется. Можно закрыть окно и исправить CSV.

### Модуль src/vfs.py

- `VirtualFileSystem.__init__` сохраняет узлы или создаёт пустой корень.
- `get_motd` возвращает текст виртуального сообщения или `None`.
- `validate_path` проверяет формат пути без обращения к диску.
- `parse_row` проверяет запись CSV и декодирует base64.
- `validate_nodes` проверяет корень и родительские папки.
- `load_vfs` открывает CSV для чтения и возвращает готовую VFS.

Класс `PurePosixPath` разбирает только виртуальные пути.
`csv.DictReader` превращает записи CSV в словари.
`base64.b64decode` восстанавливает байты содержимого.
В GUI метод `run_startup` хранит загруженную VFS и показывает motd.

### Примеры VFS

- `fixtures/minimal.csv` — только корень (1 узел), без motd.
- `fixtures/several.csv` — сообщение, текстовый и двоичный файлы,
  пустая папка (5 узлов).
- `fixtures/nested.csv` — три уровня папок и файлы (8 узлов).
- `fixtures/my vfs.csv` — пример пути к CSV с пробелами.
- `fixtures/invalid.csv` — намеренно неправильные столбцы.
- `fixtures/invalid_base64.csv` — намеренно повреждённое содержимое.
- `fixtures/invalid_parent.csv` — файл без родительской папки.

В `/motd` записано `Welcome!`, в `hello.txt` — `Hello` с переводом
строки. `data.bin` содержит байты `00 FF 41`.
Файл `repeats.txt` содержит строки `a`, `a`, `b`, `b`, `a`.

### Запуск и сценарии

Из папки приложения:

```bash
./run.sh --vfs fixtures/nested.csv --script scripts/stage3_ok.txt
```

Проверки разных VFS, выполнения команд и ошибок загрузки:

```bash
./scripts/check_vfs.sh
./scripts/check_vfs_scripts.sh
./scripts/check_vfs_errors.sh
```

Сценарии последовательно открывают 3, 8 и 4 экземпляра приложения.
Следующий экземпляр запускается после закрытия предыдущего окна.
Сценарий `stage3_exit.txt` сразу закрывает окно командой `exit`.
Ошибочные стартовые сценарии проверяют неизвестную команду, лишние
аргументы и незакрытые кавычки; строки после ошибки не выполняются.

Скрипты второго этапа обновлены для существующих CSV.
Сборка и установка сторонних библиотек не требуются.
