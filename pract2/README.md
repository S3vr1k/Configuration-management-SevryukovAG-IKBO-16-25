# Визуализация зависимостей Cargo — вариант 21

## Этап 3

Python 3, только стандартная библиотека. Запуск из pract2:

```bash
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/branching.json --test
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/cycle.json --test
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/empty.json --test
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/branching.json --test --filter B
bash run.sh --package itoa --version 1.0.15 --repository https://index.crates.io
```

Параметры: --package (имя), --version (точная исходная версия),
--repository (HTTP-адрес sparse-индекса Cargo либо тестовый JSON),
--test (локальный режим), --filter (исключаемая подстрока, регистр учитывается).
--output задает SVG-файл (по умолчанию output/graph.svg),
--ascii дополнительно выводит дерево в терминал.

Граф хранится словарем: (имя, версия) -> список таких же пар.
BFS использует очередь и множество обнаруженных вершин, без рекурсии.
Ребра к уже обнаруженным вершинам сохраняются, поэтому циклы не теряются.
Исключенный пакет и его ветвь не обходятся, но общая зависимость может
оставаться достижимой через другую ветвь. Исключение корня дает пустой граф.

Тестовый формат: имя -> версия -> список объектов с полями name и req.
Имена тестовых пакетов состоят из заглавных латинских букв.
branching: общая зависимость D; cycle: A-B-C-A; empty: пакет без зависимостей.
При --filter B в branching остаются A, C, D; цикл завершается после 3 вершин.
Это ручные сценарии демонстрации, отдельного тестового фреймворка нет.

Выбор версий: максимальная стабильная, удовлетворяющая требованию;
отозванные версии не выбираются для зависимостей. Поддерживаются ^, ~,
*, 1.*, 1.2.*, =, >, <, >=, <= и ограничения через запятую.
Предварительные версии в требованиях не поддерживаются: явная ошибка.

Анализируются все объявленные deps, включая dev/build/optional и разные
платформы. Features и глобальное согласование версий Cargo не реализованы.
Это граф объявленных зависимостей, а не точная копия Cargo.lock.
Зависимости из другого реестра не поддерживаются: явная ошибка.
Визуализация реализована на этапе 5, см. ниже.

## Этап 4: порядок загрузки

Флаг --order выводит один допустимый порядок, в котором зависимости идут
раньше использующих их пакетов. Это топологическая сортировка алгоритмом Кана,
а не предсказание хронологического порядка сетевых загрузок Cargo.

```bash
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/branching.json --test --order
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/empty.json --test --order
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/cycle.json --test --order
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/branching.json --test --filter B --order
```

Ожидается: D, B, C, A; один A; ошибка цикла; D, C, A соответственно.
Независимые B и C могут идти в любом порядке, выбран порядок обнаружения BFS.
Пустой граф после фильтрации корня не требует загрузки пакетов.

### Сравнение с Cargo — выполнено

Проверено 18.11.2026, cargo 1.100.0 (Arch Linux).
В отдельном временном проекте stage4-comparison добавлена зависимость
itoa = "=1.0.15". Использован отдельный пустой CARGO_HOME, чтобы кеш
не скрывал первоначальное скачивание. Файлы Rust-проекта не входят в работу.

Команды во временном проекте:

```bash
cargo fetch -v
cargo tree --offline
cargo build --offline -vv
```

Фактический результат fetch: Downloaded itoa v1.0.15.
Фактическое дерево Cargo:

```text
stage4-comparison v0.1.0
└── itoa v1.0.15
```

Фактический порядок строк Compiling: itoa v1.0.15,
затем stage4-comparison v0.1.0. Сборка завершилась успешно.

Сопоставимый запуск нашей программы из pract2:

```bash
bash run.sh --package itoa --version 1.0.15 --repository https://index.crates.io --filter no-panic --order
```

Фактический результат:

```text
1. itoa@1.0.15
```

В метаданных itoa 1.0.15 объявлена единственная зависимость no-panic ^0.1,
помеченная optional=true. В проекте Cargo она не включена. Наша программа
анализирует все объявленные зависимости, поэтому для сопоставления с этой
конфигурацией Cargo исключена подстрока no-panic. Это ручная настройка
сравнения, а не реализация механизма features. Метаданные проверены также
по записи индекса, сохраненной Cargo при fetch.

Порядок для itoa совпал с Cargo; временный корневой проект отсутствует
в выводе нашей программы, поскольку анализ начинается непосредственно с itoa.
Этот реальный пример проверяет пакет без активных зависимостей; ветвление,
общая зависимость, фильтр и цикл отдельно проверены тестовыми графами выше.

Порядок сборки и порядок скачивания различаются по смыслу. Для скачивания
архивов зависимости не обязаны быть скачаны раньше использующего их пакета.
При более сложных графах последовательности также могут различаться из-за
параллельной сборки, кеша, Cargo.lock, features и платформ. Наша программа
выводит один топологический порядок объявленных зависимостей.

## Этап 5: DOT, SVG и ASCII-дерево

Нужна внешняя программа Graphviz. В CachyOS:

```bash
sudo pacman -S graphviz
dot -V
```

Python-библиотеки для визуализации не нужны. Программа самостоятельно
формирует DOT и запускает dot -Tsvg. Graphviz разрешает задачу отрисовки,
а не получения зависимостей. DOT сохраняется рядом с SVG под тем же именем.
По умолчанию результаты находятся в output/, исключенной из Git.

Запуск из pract2:

```bash
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/branching.json --test --ascii --output output/branching.svg
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/cycle.json --test --ascii --output output/cycle.svg
bash run.sh --package A --version 1.0.0 --repository tests/fixtures/empty.json --test --ascii --output output/empty.svg
```

Пример ASCII-вывода для branching:

```text
A@1.0.0
|-- B@1.0.0
|   `-- D@1.0.0
`-- C@1.0.0
    `-- D@1.0.0 (*)
```

(*) означает, что вершина уже раскрыта: ее ветвь повторно не выводится.
Это также завершает вывод циклов. SVG содержит исходный граф со всеми ребрами,
а не только дерево обхода. Изолированные вершины объявляются в DOT отдельно.
При исключении корня сохраняется пустой SVG и выводится сообщение.
--order можно сочетать с --ascii; при цикле --order сообщает об ошибке
до создания изображения. Для изображения циклического графа уберите --order.

### Новые функции

- package_label: формирует подпись имя@версия.
- make_dot: превращает словарь графа в текст DOT, экранирует подписи.
- save_graph: создает выходную папку, сохраняет DOT, вызывает Graphviz,
  сохраняет SVG и переводит ошибки Graphviz в понятные сообщения.
- make_ascii_tree: обходит граф стеком без рекурсии; хранит отступы
  и множество раскрытых вершин, отмечает повторные вершины.

### Три реальных пакета и сравнение с Cargo

Проверено 18.11.2026: cargo 1.100.0, Graphviz 16.1.1.
Реальные HTTP-запуски, создавшие SVG:

```bash
bash run.sh --package itoa --version 1.0.15 --repository https://index.crates.io --filter no-panic --ascii --output output/itoa.svg
bash run.sh --package cfg-if --version 0.1.0 --repository https://index.crates.io --ascii --output output/cfg-if.svg
bash run.sh --package autocfg --version 1.0.0 --repository https://index.crates.io --ascii --output output/autocfg.svg
```

Для сравнения во временном Cargo-проекте использованы точные зависимости:

```toml
[dependencies]
itoa = "=1.0.15"
cfg-if = "=0.1.0"
autocfg = "=1.0.0"
```

Выполнены cargo fetch -v и cargo tree --offline --charset ascii.
Фактический вывод штатной визуализации Cargo:

```text
stage5-comparison v0.1.0
|-- autocfg v1.0.0
|-- cfg-if v0.1.0
`-- itoa v1.0.15
```

| Пакет | Наша визуализация | Cargo, поддерево пакета |
|---|---|---|
| itoa 1.0.15, исключен no-panic | Одна вершина itoa@1.0.15 | itoa v1.0.15 без потомков |
| cfg-if 0.1.0 | Одна вершина cfg-if@0.1.0 | cfg-if v0.1.0 без потомков |
| autocfg 1.0.0 | Одна вершина autocfg@1.0.0 | autocfg v1.0.0 без потомков |

Версии и активные связи совпали. Временный корень Cargo отсутствует
в отдельных изображениях, потому что наша программа начинает с выбранного
пакета. Обозначение версий @ вместо v и ASCII-маркеры отличаются только видом.
В itoa no-panic является optional-зависимостью и не включена в Cargo;
в программе она явно исключена фильтром для сопоставимой конфигурации.
Без фильтра наша программа анализировала бы также эту необязательную ветвь.

Все три реальных примера имеют пустые активные поддеревья. Поэтому отдельно
проверены ветвление, общая зависимость, цикл и изолированная вершина на JSON.
Проверены корректность SVG как XML и количество вершин/ребер: branching —
4/4, cycle — 3/3, empty — 1/0. Проверен вывод цепочки из 1101 вершины
без рекурсии и экранирование специальных символов DOT.
Полный учет features, платформ и согласование Cargo.lock по-прежнему
не реализованы; ограничения этапа 3 сохраняются.
